## 原因链定位

1. `paddle_ocr.py::_page_from_result`：PaddleOCR 返回 `markdown.images` 裁图 URL，代码逐张下载至 `figures/` 并把源引用替换为 `images/pNNN-N.jpg`。
2. `prompts.py` 的历史默认词要求所有图块链接「原样保留」，导致 OCR 对语法标注、文本框、彩色示意图的裁剪不会被模型主动筛掉。
3. `pdf2md.py` 的 `keep_known_figures` 只能丢弃模型编造的图片链接，不判断真实裁图是否适合文字化；最终输出无布局 HTML 清理。
4. `paddle_ocr.normalize_markdown` 已清除它自己收到的部分 `div`，上传的 `div class="analysis-box"` 一类格式更可能在第二阶段模型生成（缺少逐阶段日志，不能作为已证实结论）。
5. OCR API 的 `useChartRecognition=False` 为当前代码配置；不应直接认定这是所有图片过多的原因，应单独做同一输入的开关实验。

## 本分支改动

- 修改直接 CLI/Actions 无自定义词时的默认提示词：真正的插图保图，纯文字图块在完整转写之后才移除引用，禁止图片和文字重复以及 `div`/海量硬编码空格布局。
- 新增 `markdown_quality.clean_layout_markup`：清理已知无语义的 `div` 外壳、转 `<br>` 到 MDX 兼容写法、去除表格标签的非必要 `style` 和 `border` 属性；不删除文字、公式、图片引用和复杂表格。
- 转换器在正常模型结果及 OCR 兜底落盘前调用该函数。
- 新增回归测试与 `quality_audit.py`，可量化结构变化，筛选高图片页。

## 尚未证实的优化效果及下一步验收

此分支的结构回放证明 `div` 清理是无损的，**不能证明 1,513 张图减少，也不能证明 OCR 正确率提高**。实际对比应分别用同一 PDF 的第 7、10、75、194、252 页，保存原始 OCR Markdown、OCR 裁图、模型完整响应、最终 Markdown 和模型计费，旧版本与分支使用相同模型、参数、密钥池和提示词来源。人工对照源图检查英语句子、中文释义、箭头从句关系和图片缺失，再统计「纯文本误判成图片占比」「完整转写率」「HTML 异常数」「图片保留率」。

**部署提醒**：Remote 中保存的系统/任务提示词优先于仓库 `DEFAULT_PROMPT`；它不会因为仅合并本分支而自动更新。需要另行在 Remote 的「转换配置 → 系统提示词」同步上述图片处理规则，或者明确传入更新后的提示词。不应隐式覆盖已有自定义提示词。
