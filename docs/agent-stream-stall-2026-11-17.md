## 缺陷与修复

`observe_progress` 使用 `range(6)` 限制总连接次数。耗尽后观察协程静默退出，
主循环仍继续 checkpoint 和状态轮询；本次非终态 GET 不提供步骤，无法补回事件。
原运行没有输出重连耗尽日志，因此不能还原其每次断流的具体原因；
源码缺陷、持续心跳与上游新增事件未入库共同支持这一故障链路。

改为由主任务生命周期控制观察器，临时 HTTP/传输故障指数退避至最多 30 秒，
始终从已确认事件游标继续；首次连接尚未收到事件时也可重试。
永久 HTTP 拒绝、非 SSE 响应及无法安全重放的无游标流会输出原因。
取消仍由拥有 interaction 的主循环处理，观察器仅 GET，不重复创建或取消远程执行。
SSE 步骤数量进入累计 usage，空快照不再让前端持续看到零步骤。

配套 Remote 分支 `fix/agent-live-status` 增加执行器心跳、最近内容步骤时间、
连接失败提示和 Actions 日志入口。无新内容时执行器每 30 秒发送空进度批次，
以消息 `progressAt` 判断执行器是否在线；任务 `updated` 也由调度器刷新，不能用于此判断。
心跳与内容更新时间分开显示，避免将执行器存活误认为模型正在产出。
